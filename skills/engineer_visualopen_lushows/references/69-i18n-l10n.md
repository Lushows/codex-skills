# 69 — i18n / l10n (internacionalización y localización)

**i18n** = preparar el código para múltiples idiomas (extraer strings, formatear por locale, soportar RTL). **l10n**
= las traducciones y adaptaciones culturales reales. Primero i18n una vez; luego l10n por idioma.

## Librerías (cuándo cada una)
- **next-intl** — la elección para Next.js App Router 2026: nativa de Server Components (traducciones = 0 bytes al cliente), routing i18n integrado, ~2KB, ICU.
- **react-i18next / i18next** — framework-agnóstico, ecosistema más grande. Default para React no-Next, React Native.
- **FormatJS / react-intl** — ICU estándar, fuerte en formateo. **Lingui** — extracción en build, bundles chicos, TS. **Tolgee** — OSS con edición in-context.

## ICU MessageFormat (plurales, género, interpolación)
```
{count, plural, =0 {No tienes pedidos} one {Tienes # pedido} other {Tienes # pedidos}}
```
Maneja reglas de plural por idioma (español: `one`/`other`; otros: `few`/`many`/`zero`). `{gender, select, male{} female{} other{}}`.

## Formateo locale-aware con `Intl` (nativo, sin librerías)
```js
new Intl.NumberFormat('es-CO', {style:'currency', currency:'COP'}).format(89000);   // "$ 89.000"
new Intl.NumberFormat('es-MX', {style:'currency', currency:'MXN'}).format(1500);     // "$1,500.00"
new Intl.DateTimeFormat('es-CO', {dateStyle:'long'}).format(new Date());
new Intl.RelativeTimeFormat('es', {numeric:'auto'}).format(-1, 'day');               // "ayer"
```
COP no usa decimales típicamente; MXN sí. Separador miles/decimales cambia por locale.

## RTL (árabe/hebreo)
Usa **CSS logical properties**: `margin-inline-start` (no `margin-left`), `padding-inline-end`, `text-align: start`.
Setea `<html dir="rtl" lang="ar">`; el navegador refleja el layout. Evita `left/right` hardcodeados.

## Translation management & variantes ES
**Crowdin/Lokalise/Tolgee** sincronizan keys. Keys **semánticas** (`cart.empty`, más mantenibles) vs **naturales**
(el texto inglés como key). Workflow: extraer → subir → traducir (humano + AI pre-traducción con revisión) → bajar →
CI valida keys faltantes. **Variantes de español:** `es-CO`/`es-MX`/`es-AR`/`es-ES` difieren en vocabulario ("celular"
vs "móvil"), formalidad (tú/vos/usted), formato moneda/fecha. Decide una base (`es-419` neutro) y override por país solo donde importe. **No asumas que `es-ES` sirve para LatAm.**

## SSR / locale routing
Subpath (`/es/`, `/en/`) recomendado para SEO (URLs únicas + hreflang). next-intl gestiona middleware de detección (cookie, `Accept-Language`).

## Gotchas
1. Concatenar strings (`"Tienes " + n + " pedidos"`) rompe gramática/orden en otros idiomas. Usa placeholders ICU.
2. Plurales: español tiene 2 formas, árabe/ruso hasta 6 — no hardcodees `if (n===1)`.
3. Texto en imágenes no es traducible ni indexable; usa texto real.
4. `es-419` no siempre existe en todas las APIs; ten fallback a `es`.
5. RTL con `left/right` físicos = layout roto en árabe; audita con `dir="rtl"`.
6. Cargar TODAS las traducciones al cliente infla el bundle; split por namespace/route (next-intl en Server Components lo evita).
